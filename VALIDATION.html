Tested behavior & release limits

Release 0.1.2 · exploration encounters October 19, 2026

Passed: 16 automated integration tests

The Forge GameTest server loaded the pinned server-compatible gameplay mods, including DragonMine Z 2.1.3. The build and all 16 required tests passed.

  • Eight core tests: supply transactions and cooldowns; shop prerequisites and balances; death/clone persistence without overwriting another mod’s data; all four role files and their shared 16 chapters; remote reward and free-travel protection; bounded rival progression; localhost-only AI output sanitization; duplicate starter-guide prevention.
  • Three world tests: actual generation and safe arrivals across the custom destinations; distinct landmarks, ocean and vertical palace geometry; preservation of player block edits; different terrain profiles and far-coordinate bounds.
  • Five native integration tests: real registry items and constructible expedition bosses; eight native mentors placed safely without duplicates; all four native dimensions registered; export of the runtime item/entity registry; native encounter types and saved shared progress.

0.1.2 exploration encounters

Red Ribbon towers on new Earth and Overworld terrain and Frieza Force landing craft on new Namek and Planet Vegeta terrain contain two guards and a boss. Nearby survival contributors receive native training points after victory; sites reset after 20 minutes of world time. Existing generated chunks are not changed. Boss balance, visual layout and multiplayer rewards still need in-game playtesting.

0.1.1 control conflict update

Moves shader selection to F8 and shader reload to F9, freeing combat dash from reloading shaders. Moves offhand swap to O, accessories to I, minimap enlargement to Backslash and spacepod controls to N. Flight F, transform G, lock-on Z, dash R, charge C and mouse combat stay familiar. The eight default Inventory Profiles in-world R chords are unbound; inventory-screen R sorting stays available. Existing installations migrate once, with backups under config/dbh-control-backups. Custom keys and occupied destinations are preserved. The J guide includes a repair button.

Verification uses the actual locked client key registry and Inventory Profiles runtime to check remaps, disabled chords, retained combat bindings, custom-key preservation and repeated repair. This verifies configuration behavior, not a complete Windows combat playthrough.

Release checks

The original addon compiles and its release JAR excludes test classes. The Modrinth pack pins download URLs, exact versions, file sizes and SHA-1/SHA-512 hashes. Distributable files include SHA-256 checksums. Third-party mods are downloaded by the launcher, rather than redistributed inside the ZIP.

An isolated macOS production client completed resource loading using the locked mods. Its native window was unavailable to the UI automation surface, so this is a startup smoke check, not an in-game visual or performance acceptance pass.

What still needs player acceptance testing

  • A complete Windows Survival playthrough of all 16 expedition chapters and native race progression.
  • Animation quality in combat, every transformation and fusion, camera behavior, shader compatibility, and GPU performance on target PCs.
  • Two-account internet joining, simultaneous boss progression, disconnect/reconnect, and sustained multiplayer balance.
  • Visual inspection of original Beerus/Whis models, all generated landmarks and map sightlines in a live game.

The upstream release emits configuration-template fallback and some missing block-model warnings. It regenerates default configuration; these did not fail integration tests. This build is labeled a playtest, not a finished one-to-one anime simulation.
